# 08-电话条组件设计方案

> 本文档描述电话条的双连接架构、原生 JavaScript SDK 组成，以及在管理后台中的集成方式。
> SDK 源码位于核心私有仓库 `phonebar/`，其混淆产物与前端集成位于 `business/web/admin/`。

## 8.1 定位与基本模型

电话条是座席话务操作的统一入口：座席签入、示闲、示忙、拨号、接听、挂断都在电话条上完成。
Vocara 采用**浏览器即分机**模型：浏览器内的 SIP 软电话直接注册到 FreeSWITCH，
媒体流在浏览器与 FreeSWITCH 之间建立，呼叫中心不依赖硬件话机，也不占用额外的服务器媒体资源。

电话条在运行期同时持有两条相互独立的连接：

| 连接 | 通道 | 承载内容 |
|---|---|---|
| 业务 WebSocket | 浏览器 → vocara-push（`/ws/agent`） | 连接即签入、示闲/示忙/签出、心跳、被踢、业务事件透传 |
| SIP over WebSocket | 浏览器内 jssip → FS-Agent（明文 WS 5066） | SIP 注册、来电 INVITE、外呼、通话媒体 |

接听/挂断/拨号等呼叫动作由 SIP 通道直送 FreeSWITCH，**不经过业务 WebSocket**；
业务 WebSocket 只负责座席会话与状态。两条通道各自独立上报状态：业务 WS 的
`agent.status_change` 是座席工作状态的权威源，SIP 注册状态单独决定来电能否振铃。

```
┌─────────────────────── 浏览器（管理后台）────────────────────────┐
│                                                                  │
│   PhoneBar/index.vue（SDK 挂载壳）                                │
│        │                                                         │
│        ▼                                                         │
│   callStore（Pinia，持有 SDK 模块级单例）                         │
│        │                                                         │
│        ▼                                                         │
│   window.VocaraPhoneBar  ── PhoneBar ── Widget（vanilla DOM）     │
│        │                    │                                    │
│        ├──── WSClient  ──────────────►  vocara-push  /ws/agent   │
│        │    （业务 WebSocket）                  ▲                │
│        │                                       │ NATS + Redis    │
│        └──── SipPhone（jssip）─────────────────┤                │
│             （SIP over WebSocket）             │                │
│                                    FS-Agent :5066 / :8021(ESL)  │
└──────────────────────────────────────────────────────────────────┘
```

## 8.2 SDK 结构

SDK 为框架无关的原生 JavaScript（ES5），通过 `<script>` 标签引入，
不依赖 Vue 或任何构建时。四个源文件经 `window.VocaraPB` 命名空间串联：

| 源文件 | 职责 | 暴露成员 |
|---|---|---|
| `vocara-phonebar.js` | 入口：组合各部件、定义 PhoneBar | `window.VocaraPhoneBar.init(opts)` |
| `phonebar-ws.js` | 业务 WS 协议：连接、心跳、重连、帧分发 | `VocaraPB.WSClient` |
| `phonebar-sip.js` | jssip 封装：UA、注册、会话与远端音频 | `VocaraPB.SipPhone` |
| `phonebar-ui.js` | vanilla DOM 界面：主条、状态卡、拖拽 | `VocaraPB.Widget` |

### 8.2.1 单例语义

`VocaraPhoneBar.init(opts)` 返回 PhoneBar 实例并维护模块级单例：
再次调用 `init` 会先执行既有实例的 `destroy()`（断连并移除 UI DOM），
保证同一页面不残留多条电话条。

### 8.2.2 init 参数

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `container` | Element | 否 | 挂载容器；省略时创建右下角可拖拽浮动条 |
| `wsUrl` | string | 是 | push 座席 WS 地址，如 `/ws/agent` |
| `token` | string | 是 | admin JWT，握手时经 query 传递 |
| `extension` | string | 是 | 座席分机号（工号），同时作为业务 WS 的 `dn` |
| `sip` | object | 否 | `{ wsUri, domain, password, extension? }`；提供时启用 SIP 软电话 |
| `onSignin` | function | 否 | 电话条"签入"按钮点击回调（离线态仅渲染该按钮，正式签入由调用方执行） |
| `onStatusChange` | function | 否 | 座席工作状态回调 `(status)` |
| `onSipRegistered` / `onSipUnregistered` / `onSipRegistrationFailed` | function | 否 | SIP 注册状态回调 |
| `onIncoming` / `onAccepted` / `onEnded` | function | 否 | 来电 / 通话接通 / 结束回调 |
| `onKick` | function | 否 | 被踢回调 `(reason)` |
| `onEvent` | function | 否 | 业务事件透传回调 `(msg)` |
| `onError` | function | 否 | 错误回调 `(Error)` |

### 8.2.3 实例方法

| 方法 | 说明 |
|---|---|
| `connect()` | 建立业务 WS（连接即签入）并启动 SIP 注册 |
| `disconnect()` | 发送 signout，随后关闭 WS 与 SIP |
| `ready()` | 示闲 |
| `busy(reason?)` | 示忙/小休 |
| `answer()` | 经 SIP 接听当前来电 |
| `hangup()` | 经 SIP 挂断/拒接当前通话 |
| `dial(number)` | 经 SIP 外呼 |
| `mute(muted)` | 静音/取消静音 |
| `destroy()` | disconnect + 移除 UI DOM |

## 8.3 业务 WebSocket 协议

### 8.3.1 连接

push 服务提供三个端点：

| 端点 | 用途 |
|---|---|
| `/ws/agent` | 座席端（含班长，按座席工号路由） |
| `/ws/admin` | 管理员端 |
| `/ws/monitor` | 监控大屏端 |

握手 URL 自动拼接 query 参数：

```
wsUrl?token=<JWT>&dn=<分机号>
```

WebSocket 握手无法自定义 header，JWT 与分机号均经 query 传递；服务端以
`dn`（分机号/工号）作为座席会话的业务键。

### 8.3.2 客户端 → 服务端

客户端只发送四类 action：

| action | data | 时机 |
|---|---|---|
| `heartbeat` | — | 每 30 秒 |
| `ready` | — | 座席示闲 |
| `busy` | `{ reason }` | 座席示忙/小休 |
| `signout` | — | 座席签出 |

### 8.3.3 服务端 → 客户端

| 帧类型 | 字段 | 说明 |
|---|---|---|
| `connected` / `heartbeat` | — | 连接确认与心跳回包，不上浮业务层 |
| `session` | `action`、`data` | 会话建立结果；`ready` 返回当前状态名，`error` 返回签入失败 |
| `ack` | `action`、`ok`、`error` | 状态操作回执；失败时上浮错误提示 |
| `kick` | `data.reason` | 重复登录等场景被踢（默认 `duplicate_login`） |
| 业务事件 | 信封顶层 `event` | `agent.status_change` 等，经 `onEvent` 透传 |

业务事件信封字段：`event`、`event_id`、`timestamp`、`version`、`data`。
`agent.status_change` 事件到达时，电话条以 `data.status`（或 `status_text`）
刷新座席工作状态与状态点。

### 8.3.4 重连

- 非主动关闭、非被踢的断连，按 **5~10 秒随机退避**自动重连，最多 10 次；
- 重连成功即重新完成签入，会话在有效期内由服务端幂等恢复；
- 收到 `kick` 后本端标记被踢状态，**不自动重连**，由座席重新签入；
- 主动 `close()`（签出）不触发重连。

## 8.4 SIP 软电话

### 8.4.1 UA 参数

| 参数 | 取值 | 说明 |
|---|---|---|
| `uri` | `sip:<extension>@<domain>` | 分机地址 |
| `register_expires` | 120 | 注册有效期（秒） |
| `session_timers` | false | 不启用会话定时器 |
| `hack_ice_timeout` | 5000 | ICE 超时（毫秒） |
| 接听参数 | `mediaConstraints:{audio:true}`、`pcConfig:{iceServers:[]}` | 纯音频、不使用外部 STUN/TURN |

SIP 经明文 WebSocket（FS-Agent 5066）接入。jssip 按 URL scheme 推导 Via
传输层，电话条显式将 `socket.via_transport` 置为 `WS`，使 Via 传输与
FreeSWITCH 视角的实际传输一致。

### 8.4.2 注册事件

| 事件 | 处理 |
|---|---|
| `registered` | 透传 `onSipRegistered` |
| `unregistered` | 注册失效；若此前在线则提示"来电不可达" |
| `registrationFailed` | 透传失败原因；座席示闲不依赖 SIP，但未注册时来电无法振铃 |

### 8.4.3 会话事件

| 事件 | 时机 | 回调数据 |
|---|---|---|
| 来电（`newRTCSession` incoming） | 收到 INVITE | `{ id, caller, callee, answer, reject }` |
| 外呼（newRTCSession outgoing） | `ua.call` 发起 | `{ id, callee }` |
| `progress` | 外呼收到 180/183 | 状态卡文案切换为"等待接听" |
| `accepted` | 任一方向接通 | 远端音频绑定、通话计时开始 |
| `ended` / `failed` | 正常结束 / 失败 | 当前会话清空、状态卡收起 |

拒接以 `terminate({ status_code: 486 })` 表达。远端音频经 `peerconnection`
与 `connecting` 事件绑定，`ontrack` 与 `getRemoteStreams` 两种接口依次尝试，
由单个自动播放的 `Audio` 元素播放。

## 8.5 管理后台集成

### 8.5.1 SDK 加载

`index.html` 经两个标签引入自包含单文件（jssip 已内联）：

```html
<link rel="stylesheet" href="/phonebar/vocara-phonebar.css">
<script src="/phonebar/vocara-phonebar.js"></script>
```

加载后暴露 `window.VocaraPhoneBar`。

### 8.5.2 PhoneBar/index.vue 挂载壳

`src/components/PhoneBar/index.vue` 只承担 SDK 挂载：模板内一个容器元素，
`onMounted` 时调用 `callStore.setPhoneBarContainer(el)`，卸载时注销容器引用。
组件不接收 props、不导出方法；SDK 的 init/connect 由 callStore 统一发起。

### 8.5.3 callStore

`src/store/modules/call.ts` 是通话状态的单一数据源，持有 SDK 模块级单例。

| 状态 | 说明 |
|---|---|
| `workStatus` | 座席工作状态：`offline / checked / ready / busy / wrapup` |
| `connected` | 业务 WS 是否连接 |
| `sipRegistered` | SIP 是否注册成功 |
| `agentAuth` | `{ agentId, tenantId, extension }` 座席会话信息 |
| `currentCall` | 当前通话（`CallInfo`） |
| `callHistory` | 最近 20 条通话记录 |
| `dialPadVisible` / `dialNumber` | 拨号盘状态与输入号码 |

计算属性：`callStatus`、`isIdle/isRinging/isTalking/isDialing`、
`isInbound/isOutbound`、`displayNumber/displayName`、`formattedDuration`。

签入流程：

1. 容器就绪且管理后台已登录时，callStore 先以**离线态** init SDK：
   不连接 WS/SIP，仅渲染"签入"按钮；
2. SIP 配置由 `buildSipConfig()` 构建：注册凭据优先取"我的分机"接口
   （`tb_dn`，唯一密码源），取不到时回落环境变量；
3. 点击"签入"触发 SDK 内 onSignin → `agentSignIn()`：同实例 `connect()`，
   业务 WS 建立即完成签入，SIP 同步启动注册，UI 无重建；
4. 会话建立（CHECKED）后自动示闲，避免座席停留在 CHECKED 而不进入
   ACD 空闲池；状态以 `agent.status_change` 权威事件为准。

通话状态卡以 SIP 会话为准建立（来电 INVITE、外呼发起时）。WS 的
`call.ringing` 事件作为兜底：SIP 未注册收不到 INVITE 时仍展示来电；
WS 兜底建立的通话卡只由对应的 `call.hangup` / `call.abandoned` 清理。

副作用由 callStore 统一处理：来电铃声（`/sounds/ring1.mp3` 循环播放，
接通/挂断停止）、Naive UI 通知、系统桌面通知权限申请。

### 8.5.4 DialPad.vue

`src/components/PhoneBar/DialPad.vue` 为拨号盘弹窗，支持两种模式：

| 模式 | 用途 |
|---|---|
| `dial` | 外呼拨号，号码输入后呼叫（要求当前为空闲态） |
| `dtmf` | 通话中按键入口 |

弹窗以遮罩层居中展示，号码区、3×4 键盘与操作按钮均为本地样式。

### 8.5.5 布局常驻

电话条挂在默认布局 Header 内绝对居中的 `phonebar-wrapper` 容器中：

- 对座席与管理员角色显示（`v-show`），其余角色隐藏；
- `v-show` 保留 DOM 与通话连接，座席切换菜单/路由时来电等待与通话状态不中断；
- 左右区域伸缩不影响电话条位置。

### 8.5.6 环境变量

| 变量 | 默认值 | 说明 |
|---|---|---|
| `VITE_PUSH_WS_URL` | `/ws` | push WS 基础路径，callStore 拼接 `/agent` |
| `VITE_SIP_WS_URL` | — | SIP over WebSocket 地址；相对路径按页面协议补全 |
| `VITE_SIP_DOMAIN` | 当前 hostname | SIP 域 |
| `VITE_SIP_PASSWORD` | `1234` | 凭据回落值，正式环境由"我的分机"接口值覆盖 |

## 8.6 通话能力现状

| 类别 | 能力 |
|---|---|
| 已支持 | 签入/签出、示闲/示忙/小休、来电振铃与接听、拒接、外呼、挂断、静音、通话计时、被踢提示 |
| 暂不支持（调用即提示） | 呼叫保持、转接/咨询转接、三方通话、DTMF 发送、录音控制 |

暂不支持的能力在 callStore 中保留同名方法签名，调用时给出提示并返回 false，
供后续接入时直接补齐。监听/耳语/强插等班长能力由 callctrl 经 ESL 承担，
不在电话条范围内。

## 8.7 构建与混淆

构建脚本为核心仓库 `phonebar/build.js`，由核心仓库 `make build-phonebar` 调用：

1. jssip 依赖经 esbuild 打成压缩 IIFE（全局 `JsSIP`），第三方代码仅压缩不混淆；
2. 四个自有源文件（ws → sip → ui → 入口顺序拼接）经
   javascript-obfuscator 两轮混淆：标识符混淆、控制流扁平化、字符串数组
   base64 加密，并开启自防御；`VocaraPhoneBar`、`init`、`VocaraPB`、`JsSIP`
   等跨段协作者保持不混淆；
3. 产物 `dist/vocara-phonebar.js`（jssip IIFE + 混淆代码）与
   `vocara-phonebar.css` 同步到 `business/web/admin/public/phonebar/`。

电话条为与客户无关的通用产物，混淆用于保护自有代码；授权由 License
（设备/集群绑定）统一控制。`phonebar/demo.html` 提供 SDK 直连页面，用于无管理后台时的手工验证。
