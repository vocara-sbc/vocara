# vocara 呼叫中心系统 — 部署方案

> 本章描述 Vocara 的交付物形态、Kubernetes 部署架构与运行期配置机制。
> 部署清单位于 `deploy/k8s/`，构建流水线位于顶层 `Makefile`。

## 7.1 交付物

### 7.1.1 统一入口脚本

仓库根 `run.sh`（Linux / macOS / Git Bash）与 `run.cmd`（Windows，经 Git Bash 转发到 run.sh）是开发与构建的唯一入口，按子命令区分运行形态：

| 子命令 | 作用 |
|---|---|
| `dev [services\|web]` | 开发模式：后端 `go run` 源码 + 前端 vite dev（默认全部） |
| `build [linux\|windows\|darwin]` | 构建统一产物包到 `dist/`，默认本机平台 |
| `start [services\|web]` | 产物模式：后端运行 `dist/` 二进制 + 前端 vite dev |
| `stop` | 停止由脚本启动的进程 |
| `image <服务\|web\|all>` | 在 Linux 构建平台执行 Docker 镜像构建 |

脚本编码按解释器区分：`run.sh` 为 UTF-8 + LF；`run.cmd` 为 GBK + CRLF（cmd.exe 按系统 ANSI 代码页解析）。

### 7.1.2 产物包

`./run.sh build` 产出统一产物包 `dist/`，同时是调试联调包、裸机交付包与镜像构建的产物参照：

```
dist/
├── bin/          # vocara-admin / agentcenter / acd / callctrl / push
├── configs/      # admin.yaml、agentcenter.yaml、acd.yaml、callctrl.yaml、push.yaml
├── web/          # 前端 npm run build 全量产物（含混淆电话条与动态表单 SDK）
├── nginx/        # Windows 版 Nginx 运行时（nginx.exe + 组装好的完整 conf）
├── license/      # License 目录（单机部署时 vocara.lic 放入；Kubernetes 下经页面上传）
├── records/      # 录音目录
├── start.cmd     # Windows 一键启动（五个服务 + Nginx）
├── stop.cmd      # Windows 一键停止
└── README.md     # 产物包使用说明（源文件 deploy/README.md）
```

Windows 产物直接双击 `start.cmd` 即可运行全部服务，浏览器访问 `http://localhost`；双击 `stop.cmd` 停止。非 Windows 目标产出 `start.sh` / `stop.sh` 与供系统 Nginx 纳入 http 块的站点片段 `nginx/nginx.conf`。

产物包不含 Go 源码，呼叫控制（callctrl）以二进制交付，构建结束对此有强制检查。callctrl 配置中的录音目录在产物包内为 `./records`，其余日志、License 相对路径以产物根为工作目录生效。

License 与签发工具均不进入产物包：

- 单机部署：`vocara.lic` 经厂商单独交付，与目标机器指纹匹配，接收方放入 `license/` 目录；
- Kubernetes / 集群部署：install_id 由 admin 首次启动生成并在授权页面展示，客户凭此向厂商申请 License，收到后经页面 `/api/v1/admin/license/import` 上传，全集群经 Redis 下发生效；
- `license-cli`（核心私有仓库 `tools/license-cli`）是厂商内部签发工具，具备 License 签发与 Ed25519 密钥对生成能力，仅限厂商内部环境使用。

### 7.1.3 容器镜像

镜像构建文件位于 `deploy/docker/`，最终构建平台为 Linux：

| 文件 | 形态 | 产物 |
|---|---|---|
| `Dockerfile.backend` | golang:1.22-alpine 多阶段构建，alpine:3.20 运行层 | 四个业务服务各自独立镜像（`ARG SERVICE` / `ARG PKG` 参数化） |
| `Dockerfile.callctrl` | alpine:3.20 运行层，装载预编译二进制 | vocara-callctrl 镜像（`bin/vocara-callctrl`） |
| `Dockerfile.web` | node:20-alpine 构建前端，nginx:1.27-alpine 运行 | vocara-web 镜像（静态托管 + 统一反向代理） |
| `nginx/nginx.conf.template` | Nginx 配置模板 | 容器启动时经 envsubst 按 `VOCARA_*_ADDR` 环境变量渲染 |

镜像名与 K8s 清单对齐：`registry.example.com/vocara/vocara-<服务>:<版本>`，仓库地址可用 `VOCARA_REGISTRY` 环境变量覆盖。运行层以非 root 用户运行，含 ca-certificates 与 tzdata。

Nginx 模板的五组反向代理与 vite dev 代理（`vite.config.ts`）逐一同构：

| 前缀 | 上游 | 路径处理 |
|---|---|---|
| `/api` | vocara-admin:8080 | 不重写 |
| `/callapi` | vocara-callctrl:8083 | 重写为 `/api/v1/call` |
| `/agentapi` | vocara-agentcenter:8081 | 重写为 `/api/v1/agent` |
| `/ws` | vocara-push:8084 | WebSocket |
| `/sip-ws` | vocara-fs-agent:5066 | WebSocket，去前缀 |

### 7.1.4 构建流水线

顶层 `Makefile` 面向 Git Bash / Linux / CI 环境，统一交叉编译参数：

| 参数 | 取值 | 说明 |
|---|---|---|
| GOOS / GOARCH | linux / amd64 | 交付目标平台 |
| CGO_ENABLED | 0 | 静态二进制，目标机无 libc 依赖 |
| 构建标志 | `-trimpath -ldflags "-s -w …"` | 去除本机路径与调试符号 |
| 版本注入 | `vocara/pkg/version` 的 Version / BuildTime / GitCommit | 经 `-ldflags -X` 写入二进制 |

流水线目标：

| 目标 | 产物 |
|---|---|
| `build-business`（vocara） | vocara-admin / vocara-agentcenter / vocara-acd / vocara-push 四个业务二进制 |
| `package`（vocara） | 业务交付 tar.gz |
| `build`（core） | vocara-callctrl（linux / windows）+ 混淆电话条 |
| `sync`（core） | callctrl 二进制、混淆电话条与 callctrl 配置模板发布到 vocara |

**业务包** 含 `bin/`（四个业务二进制）与 `configs/`。核心产物不单独打包，以预编译二进制与混淆电话条随 vocara 仓库提交（`bin/vocara-callctrl(.exe)`、`configs/callctrl.yaml`、`business/web/admin/public/phonebar/`）；FreeSWITCH 配置（fs-sbc / fs-agent conf）由运维从 core 仓库 `freeswitch/` 目录直接部署。

FreeSWITCH 镜像的构建文件位于 `lib/Dockerfile.freeswitch`（构建上下文为 `lib/`，源码树 `lib/freeswitch-1.10.10`），基于 `debian/eol:bullseye` 编译 1.10.10 版本。多阶段构建文件 `lib/Dockerfile.freeswitch.multistage`：builder 阶段（`debian/eol:bullseye`）承载编译，runtime 阶段（`debian/eol:bullseye-slim`）同样注册 FreeSWITCH 官方软件源，经 apt 安装完整运行库集合——`libks`、`signalwire-client-c`、`libsofia-sip-ua0`、`libspandsp4`（build-dep 经虚拟包 `libspandsp-dev` 解析到 spandsp 3.1.x，SONAME `.so.4`）取官方源与编译产物严格同版，ffmpeg/lua5.2/libtpl/unixODBC/AMR-NB/PostgreSQL 客户端等取 bullseye 主归档版本，次级依赖由 apt 自动解析；官方源访问凭证安装后即在同一镜像层删除。安装产物经 `COPY --from=builder` 取得，运行库完整性自检在 runtime 阶段执行，镜像不含编译工具链与源码。

```bash
cd lib
docker build -f Dockerfile.freeswitch.multistage \
  --build-arg SIGNALWIRE_TOKEN=<官方源凭证> \
  -t registry.example.com/vocara/freeswitch:1.10.10 .
```

## 7.2 集群部署架构

```
   运营商网络              座席话机 / 浏览器软电话
       │                         │
       ▼ SIP                     ▼ SIP / WebRTC
┌──────────────┐  SIP     ┌──────────────┐
│  FS-SBC      │◄────────►│  FS-Agent    │
│ 接入侧媒体   │ bridge   │ 座席侧媒体   │
└──────────────┘          └──────┬───────┘
                                 │ ESL :8021
                                 ▼
┌──────────────────────────────────────────────┐
│ Kubernetes 集群（namespace: vocara）          │
│                                              │
│   Ingress: vocara.example.com (TLS 终止)     │
│      │                                       │
│      ▼                                       │
│   vocara-web (Nginx：静态托管 + 反向代理)     │
│      ├─ /api      ─► vocara-admin      :8080 │
│      ├─ /callapi  ─► vocara-callctrl   :8083 │
│      ├─ /agentapi ─► vocara-agentcenter:8081 │
│      ├─ /ws       ─► vocara-push       :8084 │
│      └─ /sip-ws   ─► vocara-fs-agent   :5066 │
│                                              │
│   vocara-mysql (8.0)  vocara-redis (7)       │
│   vocara-nats  (JetStream)                   │
└──────────────────────────────────────────────┘
```

集群内全部资源按类型划分：

| 类型 | 资源 |
|---|---|
| 前端入口 Deployment + ClusterIP Service | vocara-web |
| 微服务 Deployment + ClusterIP Service | vocara-admin、vocara-agentcenter、vocara-acd、vocara-callctrl、vocara-push |
| FreeSWITCH Deployment（hostNetwork） | vocara-fs-sbc、vocara-fs-agent（vocara-fs-agent 另含 5066 ClusterIP Service） |
| 基础设施 StatefulSet + Headless Service | vocara-mysql、vocara-redis、vocara-nats |
| Ingress | vocara-ingress（统一路由到 vocara-web） |
| 配置 | 五个 vocara-<svc>-config ConfigMap、vocara-secrets Secret |

## 7.3 业务服务工作负载

### 7.3.1 Deployment 规格

| 服务 | 副本 | 容器/Service 端口 | CPU 请求/限制 | 内存请求/限制 |
|---|---|---|---|---|
| vocara-web | 2 | 80 | 50m / 200m | 64Mi / 128Mi |
| vocara-admin | 2 | 8080 | 100m / 500m | 128Mi / 512Mi |
| vocara-agentcenter | 2 | 8081 | 100m / 500m | 128Mi / 512Mi |
| vocara-acd | 2 | 8082 | 100m / 500m | 128Mi / 512Mi |
| vocara-callctrl | 2 | 8083 | 100m / 500m | 128Mi / 512Mi |
| vocara-push | 3 | 8084 | 100m / 500m | 256Mi / 512Mi |

通用规格：

- 镜像拉取策略 `IfNotPresent`；
- Service 为 ClusterIP，端口与容器端口一致；
- 配置以 ConfigMap 经 `subPath` 挂载到容器内 `/app/config.yaml`（只读）；
- 环境变量含 `TZ=Asia/Shanghai`、`VOCARA_SERVER_MODE=release`；
- 滚动更新参数 `maxSurge: 1`、`maxUnavailable: 0`（vocara-push 为 `maxUnavailable: 1`）；
- 清单使用固定副本数，容量调整通过修改副本数或 `kubectl scale` 完成。

### 7.3.2 连接排空

- 各业务服务 `preStop` 钩子等待 10 秒，供 Endpoint 摘除与在途请求结束；
- vocara-push 承载 WebSocket 长连接，`preStop` 等待 30 秒，配合长连接读超时完成客户端断线重连到其他副本。

## 7.4 FreeSWITCH 双节点

### 7.4.1 节点职责与端口

| 节点 | 职责 | 端口（节点网络直接监听） |
|---|---|---|
| FS-SBC | 运营商接入、客户侧媒体、外呼出局 | SIP internal 5060/udp、external 5080/udp、ESL 8021/tcp、RTP 16384-32768/udp |
| FS-Agent | 座席分机注册、座席侧媒体、桥接、浏览器 WebRTC 接入 | SIP 5060/udp、external 5080/udp、SIP-over-WS 5066、SIP-over-WSS 7443、ESL 8021/tcp、RTP 16384-32768/udp |

vocara-callctrl 通过单个 ESL inbound 连接 `esl.host` 指定的媒体节点（配置指向 FS-Agent）：通道事件在该节点统一感知，座席侧呼叫在该节点发起，跨节点媒体桥接由 ESL 命令编排。运营商来话由 FS-SBC 经 SIP 中继转发至该节点。FreeSWITCH 承担媒体与协议处理，呼叫逻辑集中在 vocara-callctrl。

### 7.4.2 部署规格

| 项 | 规格 |
|---|---|
| 工作负载 | Deployment，副本数 1 |
| 镜像 | `registry.example.com/vocara/freeswitch:1.10.10` |
| 启动命令 | `/usr/local/freeswitch/bin/freeswitch -nf -nonat` |
| 网络 | `hostNetwork: true`，媒体与 ESL 端口直接占用节点网络；FS-Agent 另创建 5066 ClusterIP Service，供 vocara-web 代理 WebRTC WebSocket |
| 安全上下文 | `privileged: true` |
| 主机挂载 | `/data/vocara/freeswitch/fs-sbc`（fs-agent 对应目录）下 conf、recordings、log、certs 分别挂入 `/usr/local/freeswitch/` 对应目录；另挂 `/etc/localtime` |

RTP 端口区间约 1.6 万段，hostNetwork 模式下无需端口映射即可满足大区间媒体收发。录音经主机目录取证，交付环境可将 recordings 目录替换为共享存储。

## 7.6 配置管理

### 7.6.1 配置加载

各服务统一通过 `vocara/pkg/config` 加载单一 YAML 文件（snake_case），默认路径为服务目录下 `configs/config.yaml`，可用 `CONFIG_PATH` 环境变量指定其他路径。仓库内 config.yaml 为本机标准配置：服务监听 `0.0.0.0`，MySQL、Redis、NATS、ESL 指向 `127.0.0.1` 标准端口。开发联调环境配置放在同目录 `config.local.yaml`（中间件指向共享联调主机），该文件不纳入版本库，通过 `CONFIG_PATH=configs/config.local.yaml` 加载；统一启动脚本可用 `./run.sh dev <services|web|all> local` 切换。服务专属配置挂在同名配置节下（如 `acd:`、`callctrl:`、`push:`、`fs_dialplan:`）。

### 7.6.2 ConfigMap

集群部署不使用仓库内 config.yaml，每个后端服务对应一个 ConfigMap（`vocara-<svc>-config`），内容键为 `config.yaml`，挂载到容器 `/app/config.yaml`。ConfigMap 内 MySQL、Redis、NATS 地址为集群服务名（`vocara-mysql`、`vocara-redis`、`vocara-nats`），运行模式为 release、日志输出到 stdout。vocara-web 的上游地址经 `VOCARA_*_ADDR` 环境变量提供，镜像内默认值即同名 Service。FreeSWITCH 双节点以 hostNetwork 运行，FS-Agent 的 WebRTC WebSocket 经 5066 Service 暴露。配置项结构以 `deploy/k8s/configmap.yaml` 为准。

ConfigMap 内容变更后需重启对应 Pod 生效；Pod 模板中预留 `config-hash` 注解位，供交付流水线写入配置摘要并触发滚动更新。

### 7.6.3 Redis 逻辑库分工

集群 ConfigMap 为各服务指定独立逻辑库；仓库内 config.yaml 统一使用 db 0：

| 服务 | db |
|---|---|
| vocara-admin | 0 |
| vocara-agentcenter | 1 |
| vocara-acd | 2 |
| vocara-callctrl | 0 |
| vocara-push | 4 |

### 7.6.4 密钥与敏感信息

敏感项在 ConfigMap 内留空，经 `VOCARA_` 前缀环境变量覆盖同名配置项，由 viper AutomaticEnv 识别：

| 配置项 | 环境变量 | 适用服务 |
|---|---|---|
| app.secret_key | VOCARA_APP_SECRET_KEY | 五个服务（JWT 签名与内部服务间 X-Internal-Token，集群统一值） |
| mysql.password | VOCARA_MYSQL_PASSWORD | admin、agentcenter、acd、callctrl |
| redis.password | VOCARA_REDIS_PASSWORD | 五个服务 |
| nats.password | VOCARA_NATS_PASSWORD | 五个服务 |
| esl.host | VOCARA_ESL_HOST | callctrl（FS-Agent 节点 IP） |
| esl.password | VOCARA_ESL_PASSWORD | callctrl |
| acd.agent_center_token | VOCARA_ACD_AGENT_CENTER_TOKEN | acd（与座席中心 app.secret_key 同值） |
| fs_dialplan.sbc_peer / agent_external / gateway | VOCARA_FS_DIALPLAN_SBC_PEER / _AGENT_EXTERNAL / _GATEWAY | admin |

vocara-callctrl 统一引用 Secret `vocara-secrets`（键 `db-password`、`redis-password`、`nats-password`、`esl-password`）；其余清单内为占位明文，交付环境统一收敛到 Secret。

## 7.7 网络入口

### 7.7.1 入口链路

浏览器与座席浏览器的全部请求经单条链路接入：

```
NGINX Ingress (TLS) -> vocara-web:80 (Nginx) -> 各后端 Service
```

`vocara-ingress` 面向 `vocara.example.com`，由 NGINX Ingress Controller 承载，规则为前缀全量透传到 vocara-web；五组分发（`/api`、`/callapi`、`/agentapi`、`/ws`、`/sip-ws`）由 vocara-web 容器内 Nginx 完成，分发规则即 7.1.3 的同构表。

注解规格：请求体上限 10m，连接超时 30s，发送/读取超时 60s，开启 gzip；`/ws`、`/sip-ws` 的协议升级（`Upgrade`/`Connection` 头）与 3600s 读写超时在 vocara-web Nginx 配置内生效。

### 7.7.2 TLS

Ingress 的 TLS 段在清单中以注释形式保留，交付环境填入证书资源后启用；浏览器软电话经 Ingress 终止 TLS 后，由 vocara-web 到 vocara-fs-agent 的 WebSocket 为集群内明文连接。自签证书需在客户端先行信任。

## 7.8 健康检查

全部微服务暴露 `/health` 端点：

| 探针 | 方式 | initialDelay | period |
|---|---|---|---|
| readinessProbe | HTTP GET `/health` | 10s | 5s |
| livenessProbe | HTTP GET `/health` | 30s | 15s |

未就绪 Pod 不进入 Service Endpoint；滚动更新期间新副本 Ready 后旧副本才开始摘除。

## 7.9 部署顺序

1. 创建 namespace（`namespace.yaml`）；
2. 应用 ConfigMap 与 Secret（`configmap.yaml`）；
3. 部署 MySQL、Redis、NATS 三个 StatefulSet，确认 Pod Running 且 Ready 1/1；
4. 部署 vocara-admin、vocara-agentcenter、vocara-acd、vocara-callctrl、vocara-push；
5. 部署 FS-SBC、FS-Agent（节点需具备 hostPath 目录与特权权限）；
6. 部署 vocara-web；
7. 应用 vocara-ingress。

## 7.10 交付环境安全事项

- ConfigMap 内敏感项留空，清单环境变量中的口令与密钥均为占位值，交付前必须替换，并统一收敛到 Kubernetes Secret；
- 为 Ingress 启用 TLS；浏览器软电话使用 WSS，自签证书需在客户端先行信任；
- MySQL、Redis、NATS 均为单实例 StatefulSet，存储依赖单节点 PVC，适用于开发测试与小规模交付；多节点交付场景由实施方提供高可用基础设施后再行接入；
- FreeSWITCH 以 hostNetwork + 特权容器运行，节点需纳入容器安全基线管理。
