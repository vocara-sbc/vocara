# 06-数据库表设计

> 本文档与 `db/migrations/001_init_schema.sql` 保持一致（DDL 以基线脚本为准，本文档说明设计原则与表间关系）。

## 一、命名规范

| 规则 | 约定 | 示例 |
|---|---|---|
| 表名 | `tb_` 前缀 + 业务语义 | `tb_agent`、`tb_inbound_route`、`tb_line` |
| 主键 | `id`（bigint unsigned 自增） | — |
| 主键引用 | `xxx_id`（bigint unsigned） | `agent_id`、`skill_group_id`、`queue_id` |
| 工号/号码字符串 | `xxx_number`（varchar） | `agent_number`（座席工号）、`dn_number`（分机号）、`did`（接入号） |
| 编码字段 | `xxx_code`（varchar） | `tenant_code`、`skill_code`、`route_code`、`instance_code` |
| 时间字段 | `created_at` / `updated_at`（datetime(3)，由应用层维护） | — |
| 租户字段 | `tenant_id`（bigint unsigned） | — |
| 状态字段 | `status`（1-启用 0-禁用），状态机单独注释 | — |
| 索引 | 唯一索引 `uk_xxx`，普通索引 `idx_xxx` | `uk_tenant_agent_number`、`idx_queue_id` |

## 三、核心关系

```
tb_tenant 1─n 全部业务表（tenant_id 隔离）

tb_agent n─1 tb_organization     经 tb_agent.group_id（组织机构归属）
tb_agent n─n tb_skill_group      经 tb_agent_skill（agent_number 工号冗余，agentcenter 直查）
tb_agent 1─1 tb_dn               tb_agent.dn_number ⇄ tb_dn.dn_number（tb_dn.agent_id/agent_number 反查）

tb_inbound_route n─1 tb_queue         呼入路由定目标队列
tb_inbound_route n─1 tb_skill_group   技能组限定（空=不限）
tb_inbound_route n─n tb_holiday_schedule  holiday_ids(JSON)

呼叫数据流：
  tb_inbound_route(did) → 客户排队(tb_queue) → ACD 分配（tb_agent_skill 技能过滤 + tb_online_agent 空闲）
  → 通话(tb_call_record 汇总) / 座席服务明细(tb_agent_service_record)
```

## 四、关键设计说明

1. **座席三类标识**：`id`（主键，表间引用）、`agent_number`（工号，登录账号/业务标识）、`agent_name`（姓名展示）。跨服务（agentcenter/ACD/push）统一以 `agent_number` 为座席业务键。
2. **分机表与接入号路由分离**：`tb_dn` 存可注册的 SIP 分机（含密码）；接入号（DID）落在 `tb_inbound_route`，是路由规则而非注册端点。全库仅 `tb_call_record` 使用 RANGE 原生分区，不存在其他分表策略。
3. **SIP 凭据单源**：`tb_dn.password` 为唯一密码源；FS 经 mod_xml_curl 的 directory binding 实时查询，新建分机即建即用。
4. **呼入路由单源**：`tb_inbound_route` 为 DID 路由唯一数据源；callctrl 定时拉取构建缓存，admin 变更发布 `inbound_route.change` 事件（主题 `vocara.event.inbound_route.change`）即时刷新。
5. **CDR 分区**：`tb_call_record` 按 `YEAR(start_time)` RANGE 分区（p2025–p2028 + pmax），唯一索引均含分区列。
6. **名称冗余列**：`queue_name`/`skill_name`/`agent_name` 等为展示冗余（避免列表页 join），以主表为准，关联写时同步更新。
